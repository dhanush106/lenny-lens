# LennyLens

**LennyLens** is a grounded product research assistant and artifact engine built over *Lenny’s Podcast* transcripts. It helps product managers, founders, and growth leaders extract actionable, evidence-backed insights, generate structured Ship 30 for 30 essays, and render sandboxed HTML/Markdown strategy artifacts—strictly grounded in podcast transcript evidence.

---

## Overview

Product teams often spend hours searching through unstructured audio transcripts and interview notes for proven frameworks on product discovery, execution, activation, and growth loops. Generic LLM chatbots frequently hallucinate frameworks or quote out-of-context anecdotes.

**LennyLens** solves this by enforcing strict, verifiable transcript grounding. Every response, essay, and artifact generated by LennyLens is directly cited against indexed podcast excerpts, ensuring zero hallucinated advice.

### Core Capabilities
- **Grounded Q&A:** Natural language queries answered strictly from indexed transcript evidence with inline citation tags `[1]`, `[2]`.
- **Ship 30 for 30 Essay Generator:** Turn product topics into structured 300-word atomic essays adhering to the Ship 30 playbook.
- **Interactive Product Artifacts:** Generate self-contained HTML strategy canvases, comparison tables, vertical timelines, and Markdown briefing documents.
- **Flexible Model Selection:** Switch seamlessly between local on-device models (Ollama/Qwen) and cloud LLM providers (OpenAI, Anthropic, OpenRouter) in memory without restarting services.
- **Multi-Modal Retrieval Engine:** Hybrid lexical (PostgreSQL `tsvector`) and semantic vector (Ollama `nomic-embed-text` + `pgvector`) retrieval with concept-aware reranking and transcript diversification.

## Features

### Currently Implemented
- [x] **Natural Language Product Q&A:** Context-aware Q&A with inline citations.
- [x] **Source Footnotes & References:** Interactive source cards displaying guest names, transcript excerpts, episode titles, and timestamps.
- [x] **Ship 30 for 30 Essays:** Dedicated skill generating structured atomic essays with full citation footers.
- [x] **HTML & Markdown Artifacts:** Generation of sandboxed HTML one-pagers, CSS-styled strategy canvases, comparison tables, and vertical timelines.
- [x] **HTML Security & Sandboxing:** Automatic script stripping, CSP policy injection, and safe `<iframe>` sandbox rendering.
- [x] **Hybrid RAG Retrieval Engine:** Lexical search (`tsvector`), vector search (`pgvector`), intent-based reranking, and multi-transcript diversification.
- [x] **Deterministic Grounding Pipeline:** Claim extraction, token overlap confidence scoring, and automatic fallback artifact generation when prose fails claim verification.
- [x] **Dynamic Runtime Configuration:** Change LLM provider and model on the fly in memory via `/api/v1/runtime`.
- [x] **Local & Cloud Provider Support:** Ollama (`qwen3.5:2b`), OpenAI (`gpt-4o`, `gpt-4o-mini`), Anthropic (`claude-3-5-sonnet`), and OpenRouter.
- [x] **Conversation Session History:** Multi-session persistence in PostgreSQL with conversational context expansion for follow-up questions.
- [x] **Radically Minimal Editorial UI:** Premium light-theme interface built with custom palette (`Chalk`, `Stone Laurel`, `Forest Umber`, `Fennel`) and typography (`Newsreader`, `Inter`, `JetBrains Mono`).

### Planned / Not Currently Implemented
- [ ] **Multi-User Authentication:** *(Planned / Not currently implemented)* - Currently defaults to a single demo user account (`user_id = 1`).
- [ ] **PDF / DOCX / CSV Artifact Exporting:** *(Planned / Not currently implemented)* - The pipeline currently supports HTML and Markdown; requesting unsupported formats returns an explicit format error.
- [ ] **Automated Web Scraping / Live Episode Ingestion CLI:** *(Planned / Not currently implemented)* - Transcripts are seeded via `seed_db.py` from local JSON files.
- [ ] **Persistent API Key Vault:** *(Planned / Not currently implemented)* - API keys are held strictly in server memory per session for security.

## Prerequisites

To run LennyLens locally or via Docker, ensure you have the following installed:

- **Docker & Docker Compose** (v2.0+)
- **Node.js** (v20.0+) & **npm** (v10.0+)
- **Python** (v3.11+)
- **PostgreSQL** (v15+) with `pgvector` extension (if running without Docker)
- **Ollama** (optional, for local model inference; recommended: `ollama pull qwen3.5:2b` and `ollama pull nomic-embed-text`)

---

## Installation

### Option A: Running with Docker Compose (Recommended)

1. **Clone the repository:**
   ```bash
   git clone https://github.com/dhanush106/lenny-lens.git
   cd lenny-lens
   ```

2. **Configure environment variables:**
   ```bash
   cp .env.example .env
   ```

3. **Build and start the containers:**
   ```bash
   docker compose up -d --build
   ```

4. **Seed the database with transcript data:**
   ```bash
   docker compose exec backend python seed_db.py
   ```

5. **Access the application:**
   - **Frontend UI:** [http://localhost](http://localhost) (or [http://localhost:80](http://localhost:80))
   - **Backend API Docs:** [http://localhost:8000/docs](http://localhost:8000/docs)

---

### Option B: Local Development Setup (Manual)

#### 1. Database Setup
Start PostgreSQL with `pgvector` enabled:
```bash
docker run -d --name lennylens-db -p 5433:5432 -e POSTGRES_USER=user -e POSTGRES_PASSWORD=password -e POSTGRES_DB=lennylens pgvector/pgvector:pg15
```

#### 2. Backend Setup
```bash
# Create and activate virtual environment
python -m venv .venv
# On Windows:
.venv\Scripts\activate
# On macOS/Linux:
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Run database migrations and seed transcript data
alembic upgrade head
python seed_db.py

# Start FastAPI dev server
uvicorn backend.main:app --reload --port 8000
```

#### 3. Frontend Setup
```bash
cd frontend
npm install
npm run dev
```
Open [http://localhost:5173](http://localhost:5173) in your browser.

## Environment Variables

Defined in `.env` (refer to `.env.example` for defaults):

| Variable | Default Value | Description |
| :--- | :--- | :--- |
| `DATABASE_URL` | `postgresql+asyncpg://user:password@localhost:5433/lennylens` | PostgreSQL connection string |
| `LLM_PROVIDER` | `ollama` | Default LLM provider (`ollama`, `openai`, `anthropic`, `openrouter`) |
| `OLLAMA_BASE_URL` | `http://host.docker.internal:11434` | Ollama service endpoint |

| `RETRIEVAL_TOP_K` | `5` | Top chunks to retrieve per search |
| `GROUNDING_MIN_CONFIDENCE` | `0.45` | Minimum token overlap score for claim verification |
| `OPENAI_API_KEY` | *(optional)* | OpenAI API key for cloud inference |
| `ANTHROPIC_API_KEY` | *(optional)* | Anthropic API key for Claude models |

## API Reference

### Health & Runtime Endpoints
- `GET /api/v1/health` - Liveness check. Returns `{"status": "ok"}`.
- `GET /api/v1/ready` - Readiness check. Verifies database connectivity.
- `GET /api/v1/runtime` - Returns active LLM provider, model, and retrieval settings.
- `PUT /api/v1/runtime` - Updates active LLM config in server memory.
- `POST /api/v1/runtime/models` - Fetches available models from Ollama or cloud providers.

### Session & Chat Endpoints
- `GET /api/v1/sessions` - List user chat sessions.
- `POST /api/v1/sessions` - Create a new chat session.
- `GET /api/v1/sessions/{id}/messages` - Fetch session message history.
- `POST /api/v1/sessions/{id}/chat` - Main grounded interaction endpoint. Accepts user prompt, performs RAG retrieval, runs intent skill, validates claims, and returns answer + sources + artifact payload.
